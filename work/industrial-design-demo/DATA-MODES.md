# 本地 MySQL 与数据模式

当前网页：http://127.0.0.1:5174/#display

## 启动

1. 在项目根目录执行 `.runtime/scripts/run-mysql.ps1`，使用已有 MySQL（127.0.0.1:3307）。
2. 在本目录配置 `.env.local`，字段见 `.env.example`。不要将密码或遥测令牌放入前端 VITE_ 变量。
3. 执行 `npm run dev -- --port 5174 --strictPort`。

当前使用 Node 服务和 MySQL；没有切换到 Java 服务。MySQL 连接失败会报错，不回退 SQLite。
业务表：runtime_state、production_tasks、event_logs、service_settings（AI 配置）。
SQLite 仅保留作迁移源/备份，`migrate-sqlite-to-mysql.mjs` 只向空目标迁移，应用正常运行不再打开 SQLite。
AI 配置首次读取时迁入 MySQL；旧 JSON 仅保留作首次迁移源。

## 三种模式

- 模拟：本地任务驱动虚拟设备。
- 真实：从认证网关接收实体设备遥测，不生成随机工艺数据。
- 混合：已绑定设备的有效真实遥测优先；未接入或超过设备新鲜度阈值时，自动显示任务驱动模拟并标注来源。下发任务只启动模拟工位，不向实体设备发送命令；整体库存/产量尚不计算，以免把部分真实工位推测成完整生产结果。

首次进入页面弹出选择器，顶部按钮可再次切换。模式属于整条产线，三个终端共享。
任务和运行快照按模式隔离；员工、知识库和模型配置共用。日志保留 dataMode。
真实工位超过配置的新鲜度阈值（默认 15 秒）未上报：真实模式显示离线，混合模式显示模拟补位；离线仅表示数据不可用，不是物理停机确认。
真实库存、批次和产品位置未接入时显示待接入；设备模型动画仍是状态驱动示意，不是物理位置追踪。

## 实体网关接入

网关把 PLC/OPC UA/Modbus/MQTT 遥测转换为 HTTP JSON：

POST /api/ops/telemetry
Authorization: Bearer <本机 .env.local 的 TELEMETRY_TOKEN>
Content-Type: application/json

```json
{
  "mode": "real",
  "origin": "physical",
  "stageIndex": 0,
  "deviceId": "WASH-PLC-01",
  "timestamp": "替换为当前 ISO UTC 时间",
  "value": 42.2,
  "rate": 120,
  "state": "running"
}
```

工位索引 0–8；state 可为 running/stopped/warning/fault。混合模式使用 mode=mixed。先在运营管理 → 设备接入启用标准 HTTP 遥测并绑定 deviceId；不匹配的编号拒收。模式切换清空遥测，需网关重新上报。
value 单位遵循该工位页面；rate 为瓶/min。服务验证令牌、有限数值、时间新鲜度与递增顺序。origin 字段是网关声明，不能单凭它证明实体来源，需要实际部署时绑定可信设备网关。
入口目前监听本机，远程硬件需通过受控 HTTPS/VPN 网关接入；不要把 MySQL 端口直接开放到公网。
尚未配置设备命令网关与执行回执，因此真实模式禁止下发启动、人工改写设备状态或演示自动调参。

## 运营管理：设备接入

- `GET /api/ops/connections`：管理员和工程师读取九工序的接入配置及诊断状态。
- `POST /api/ops/connections`：管理员保存配置，带 `stageIndex` 和当前 `version`；冲突返回 409。MySQL 保存配置，操作写入日志。
- `POST /api/ops/connections/diagnose`：仅检查本地配置和接收记录，不连接设备。
- HTTP 接收器已实现。PLC（Modbus/MQTT）、机械臂 TCP、相机、PDA、AGV 为配置草案模板，未实现对应驱动，不允许启用。
- 每工序绑定一个聚合遥测设备，支持 value、rate、state 以及下方固定的附加测点与过程反馈；不是任意 PLC 寄存器映射器。
- 真数据保存在独立 telemetry 中，不覆盖中央模拟状态。超时回退、恢复真实来源写入事件日志。
- 接收启用的真实目标在混合回退期间仍禁止模拟控制按钮改写；真实命令网关、急停及执行回执尚未接入。
- 本机网页沿用演示身份权限机制，不是生产环境身份认证。配置中不录入密钥，网关令牌配置在服务端环境文件。

### 统计和记录边界

`daily-metrics.mjs` 按北京时间日界累计本次模拟生产的新增数量，以模式和日期分别保存到 MySQL runtime_state。旧累计量不回填当天，缺失小时为 null。真实/混合模式尚无实际生产计数器，产出展示未接入，不用节拍推算。物流按当日已完成流水求和，当前物流仍标注模拟。

AI 决策追加带 stageIndex 的事件日志，记录来源、置信度、审核配方版本、参数前后值与是否实际应用。转人工和联锁暂停另行标识；只读匹配不显示成已经执行。工位日志严格筛选工位，三端日志按当前数据模式隔离。历史仅有全线记录的决策可显示最近关联摘要，不伪造分工位历史。真实设备命令网关仍未连接。

## 原始资料、标准数据与 MCP（2026-10-06）

入口：运营管理 → AI 知识与策略 → 资料整理与标准数据。

- 原始资料继续使用现有 TXT / MD / CSV / JSON 正文导入；编辑前版本进入 `documentHistory`，整理任务另外保留不可变来源快照。
- `standardDrafts` 保存提取字段、逐字引用、AI 问题、人工补充、问题处理依据及修订历史；`standardRecords` 保存人工发布的产品、设备档案和工艺配方版本。
- 这些记录由现有 MySQL `runtime_state` 事务持久化，操作日志进入 `event_logs`，不是浏览器本地存储。当前是逻辑分区，未新增独立关系表。
- AI 提取使用已配置的决策模型。调用期间草稿版本变化会拒绝覆盖；模型失败保持原稿；缺失和冲突需人工处理。
- 产品发布同步产品资源；设备数据仅为标准档案，不自动改写控制能力上下限；配方发布生成已审核的确定参数，并保留历史版本。源文档更新不会自动覆盖已发布配置。
- 应用配方只接受记录编号与版本，服务端读取参数；检查模式、联锁、产品任务匹配、工位权限、范围与单位。仅模拟设备执行，执行后暂停，回读及前后值进入 `standardExecutions`。相同请求编号重复提交返回原结果。

### 外部 MCP

协议：Streamable HTTP 的 JSON 响应模式，协商版本 `2025-03-26`，地址 `http://127.0.0.1:5174/api/ops/mcp`。支持 initialize、ping、tools/list、tools/call 和初始化通知，不提供 SSE 订阅。外部 AI 客户端尚未在本项目配置。

在本地 `.env.local` 配置 `MCP_CONTROL_TOKEN`（自行生成至少 32 字符的随机值，不要放入 VITE_ 变量），可通过 `MCP_ACTOR_ID` 指定现有启用账号，默认 engineer；重启服务。客户端设置 `Authorization: Bearer <本地令牌>`。未配置令牌返回 503；令牌错误返回 401。现有网页演示身份并非公网认证体系，此入口保持本地使用。

工具：
- `list_standard_data`：返回各目标当前版本和标准字段。
- `apply_recipe`：参数为 `recordId`、`version`、`requestId`、`confidence`。需工程师权限及开启模拟自动调参，禁止携带临时参数。
- `get_execution`：按 `requestId` 查询执行记录。

网页图片识别匹配到标准配方时调用同一工具执行器；聊天仍只问答，不直接下发控制。操作界面也可人工确认应用模拟配方。

验证：`node --test knowledge-workflow.test.mjs daily-metrics.test.mjs logistics.test.mjs`。


### 产品固定模板入口调整

产品资源分为“产品本身”“生产工艺”，目录与展示素材另页维护。在线表单及 JSON 模板共用后端校验；JSON 顶层固定为 templateVersion、kind、targetId、values、basis，版本为 1。产品六个字段必须填写，工艺参数仅允许现有 NUMBER/TEXT 控制能力。AI 审核已填项，不重复生成参数；人工确认发布才写入正式版本，审核失败需纠正重新提交。草稿仍保存在 MySQL，可从产品内继续审核。独立配置 → 数据库只读展示标准版本及审核草稿。已取消独立的原始资料审核菜单，既有资料保留；设备资产模块未改动。


### 管理中心工作区

- 管理中心分为运营决策、工程管理。运营历史以 dailyMetrics 的北京时间增量统计为准，产品结构另标明现存任务累计口径，不伪造历史质量、停机或财务指标。
- 运营方案 strategies 可提出产品产量或物料备料目标，采用后通过工程管理的方案承接关联现有任务。禁止把其他产品任务关联进来；方案不自动下发设备，也不重复生成任务。
- 产品详情按原料配方 formulas（基准批量、原料用量、步骤）和设备工艺分开。工艺修改发布新版本，删除生效工艺实际为停用并保留证据。停用的标准版本不能经 MCP 应用。
- materialUsage 按模式、物料、日期保存人工登记的计划和已用量，修改需要说明；库存仍在材料台账中独立维护，不自动重复扣减。
- 设备图片可上传 PNG/JPEG/WebP，最大 1.4 MB，保存在已有 MySQL 资产数据中；默认复用各类设备 SVG 示意图。卡片不按工序强制分行，工序为筛选分类。


### 四路实际相机与上料区

工位终端外观检测支持“模拟画面 / 实际画面”切换。模拟画面为数据驱动的三维视角，不是实体视频。管理员或工程师可通过“实际摄像头接口”保存四个固定机位的 HTTP/HTTPS 地址（`POST /api/ops/cameras`，`items: [{id,type,url}]`，type 为 video 或 mjpeg）；配置存入 MySQL preferences.cameraSources。空地址、连接失败或连接超时显示“暂无实际画面”。video 依赖浏览器支持的编码/协议，RTSP、RTMP 和需专有登录的相机需另配视频网关；不把用户名密码写进 URL。未提供真实相机地址时仅验证空状态和接口，不代表实体设备已接入。

MG400-TEACH-01 资产复用原有 Robot_Loading_Cycle，在瓶体预处理入口增加备瓶台、夹指、三种瓶形及输送带延长段。整个上料区随资产位置、角度和缩放一起调整，停用资产隐藏区域。取放为八秒预设动作，跟随第一工位运行/暂停/离线状态，未表示真实关节或抓取成功反馈，不累计实际产量。无任务或暂停时不自动启动产线。


### 模拟物料顺序与设备动作

普通模拟模式下，下发任务创建空的物料队列。设备启动表示就绪，上料机械臂按取放周期送瓶，依次经过预处理、气检、视觉、灌装、复检、装箱、运输、入库。备液可并行进行。下游未到料不加工；装箱按任务包装规格集齐，尾批允许不足一箱。库存按上料预留，完成量只在入库后累计。暂停保留队列与进度，新任务创建新队列，已完成的历史产量不重算。

三维瓶体、设备加工动作、四路模拟相机和二维动作共用后端 materialFlow。时间依据当前清洗、采样、静置、灌装等设定及演示输送时长，属于顺序流程模拟，不表示设备实测节拍。真实和协议模式尚未提供逐瓶到位反馈时显示“等待到料反馈”，不依据设备启动状态自动铺满瓶体。


### 空瓶与成品检测

外观检测（第 3 工位）检查空瓶瓶口、瓶身污渍及裂纹；二次检测（第 6 工位）面向灌装成品，关注液位、瓶盖到位和封口外观。两处均为顶部一台、侧面 0° / 120° / 240° 三台相机，支持四路同屏、单路、模拟/实际切换。二检保留 SEC-CAM-01 作为顶部相机，新增 SEC-SIDE-01/02/03 与 SEC-LIGHT-01；液位曝光仍使用 SEC-LEVEL-01。两组地址分别保存，保存一组不覆盖另一组。模拟图像按各自工位的物料队列显示，尚未接入图像缺陷识别，不能把画面当作合格结论。

## 工位核心数据与过程反馈

工位核心数据按当前工位来源展示。真实遥测不继承本地模拟值；混合模式逐工位采用新鲜遥测，补位读数标注为模拟。协议仿真仅显示协议已回读的测点。未提供的字段显示“—”或“未提供”；离线、缺测与明确上报的零值分别处理。无逐瓶反馈不推断为零瓶，无备液进度不推断为 0%。

`measurements` 可提供所属工位的以下数值测点（名称及单位与工位核心信息一致）；既有完整控制点编号仍兼容接收。数值必须有限，百分比为 0–100。

| 工位索引 | 测点 |
|---|---|
| 0 | washPressure (MPa)、washFlow (L/min)、airFlow (L/min) |
| 1 | chamberPressure (kPa)、gasTemperature (°C) |
| 2 | inspectionPassRate (%)、inspectionIlluminance (lx) |
| 3 | tankLevel (%)、mixConcentration (°Bx) |
| 4 | fillDeviation (mL)、actualFillFlow (mL/s) |
| 5 | actualLiquidLevel (mm)、sealPressure (kPa) |
| 6 | gripperVacuum (kPa)、actualGripForce (N) |
| 7 | batteryLevel (%)、obstacleDistance (m) |
| 8 | warehouseTemperature (°C)、warehouseHumidity (%RH)、warehouseGas (%LEL)、warehouseSmoke (0/1) |

可在遥测包中附加以下字段；所有字段表示本次回传状态，下一包缺失即显示未提供，不沿用旧样本：

- 工位 0：`washPhase` 为 waiting / arriving / rinse / air / leaving，分别表示等待、入位、水洗、风洗、移交。水风洗效果使用回传流量；需同时回传在制状态才能展示实际处理动画。
- 工位 1：`inspection: {bottles: [{id: "B-001", duration: 90, elapsed: 12, status: "testing"}]}`。实际在位最多四瓶，时间单位秒，status 为 testing / paused / done。空数组表示明确无瓶，缺字段表示状态未知。界面直接使用设备回传时间，不用网页本地计时推算。
- 工位 3：`prepProgress: 45`，范围 0–100，表示料液准备进度。
- 各工位：`material: {count: 2, processing: true, phase: "processing"}`，count 为实际在制数量，phase 为 waiting / processing / holding / leaving。未回传物料时不根据“已启动”推断有瓶或正在加工，也不虚构瓶体运动轨迹。

模拟模式的产出为本工位最近一分钟实际模拟移交数量；其他模式的 rate 标注为“工位回传速率”，采用设备给出的瓶/min，不能当成网页统计的近一分钟完成量。


## 装箱、运输和仓库安全

模拟模式采用同一箱 ID：MG400 逐瓶抓取 → 达到任务每箱瓶数 → 封箱 → 满箱运输 → 仓库升降移载 → 写入库存及出入库流水。未满尾箱不运输；库位不足时保留待入库箱，不能增加已完成产量。库存单位为箱，流水另存瓶数；货架箱体是占用示意，准确数量以库位台账为准。当前模拟入库默认到期日为入库后 180 天，仅为演示批次约定，不代表任何饮料的实际保质期。

| 仓库测点 | 预警 / 严重阈值 | 模拟联动与恢复 |
| --- | --- | --- |
| 温度 | ≥32 / ≥35 °C | 35 °C 场景启动排热风机，降到30 °C退出 |
| 湿度 | ≥65 / ≥75 %RH | 75 %RH 场景启动除湿机，降到65 %RH退出 |
| 可燃气体 | ≥10 / ≥20 %LEL | 声光提示并停止运输、入库；排查后人工复位 |
| 烟感 | 信号1为严重告警 | 停止运输、入库，关闭排热风机，声光提示；排查后人工复位 |
