# 物流空间与仓储

入口：大屏概览中央“物流与仓储现场”进入只读场景；工位 8、9 默认展开三维物流，承担规划、预览、执行与避障操作。运营管理使用纵向导航，仅保留运输任务、策略、库存、流水和现场跳转入口。

## 当前可用

- 同一份 `src/logistics.js` 空间定义用于 SVG 地图、Three.js 场景和后端寻路。Blender 对应布局快照在 `logistics-layout.json`，可编辑场景为 `logistics_spatial.blend`。
- 2D 复用现有 `Equipment` SVG，3D 复用设备 GLB 和原工厂建筑构件材质。`logistics-environment.glb` 从现有厂房提取 147 个建筑构件，按物流坐标布置，独立保存 `logistics_environment.blend`；原设备与原场景文件未覆盖。GLB 中无设备归属的默认 Cube 不纳入新场景。
- 两种视图默认先展示 3D；共享 `spatialZones` 和 `navigationCells`。导航网格直接来自寻路的 `blocked()` 判定，静态禁行区域包含设备安全间隙。分区配色仅是视觉标记，不改写通行权限。
- 生产蓝、仓储紫、收货金、发货绿；可通行道路用青灰，禁行用灰色（2D 带斜线），临时障碍用红色。右上角提供图例。厂区环境、区域分色、通行禁行、路线、图例可分别开关；开关只影响显示，不取消避障约束。小屏图例排在地图上方，避免遮挡。
- 地面纹理由 Lovart / GPT Image 2 生成，位于 `public/images/logistics-floor.webp`。生成图只作材质底图，不承担地图、障碍或路线判定。项目：https://www.lovart.ai/canvas?projectId=2rsbxvox1hj4 。
- A*、Dijkstra、BFS 均实际计算路线。在等权四邻接网格中最短距离可能相同，展示搜索节点数区分搜索工作量。障碍物边界留出车辆半宽和间隙。
- 入库策略：就近空位、按产品分区（优先专属区，再使用共享区）、均衡库区占用。
- 出库策略：先进先出、临期优先；排除过期批次。首版每任务对应一个足量批次，暂不跨库位拆单。
- 单车任务包含空车接货与载货配送。支持暂停、恢复、接货前取消。接货后保持任务与货物关系，不能直接取消。
- 临时障碍：2D 点击网格或输入坐标添加，3D 同步显示实体障碍和安全区。动态障碍向周围膨胀一格，保护车辆空间。当前是网格级避障，不是 DWA 连续速度控制或实体碰撞传感器。
- 避障策略：重规划（沿当前任务所选 A* / Dijkstra / BFS 重新计算）或停车等待。重规划保留接货阶段和库存关联；无路可走进入“避障等待”，道路恢复后继续。人工暂停不会自动恢复。
- 调度候选：FIFO、优先级、最近接货点排序。不提前锁定库存，单车空闲后人工确认下发，后端重新校验。无库存或无路的候选不可下发。
- 多库位线路：最近邻、最近邻 + 2-opt，显示原始顺序、最近邻基线及优化结果。空库位可作巡检点；此模块只预览，不执行多库位搬运，也不改库存。
- 库位对比：同一入库请求下比较三种策略的库位、距离、预计时间。
- 库存分析：ABC 基于当前数据模式中已完成出库箱数的累计占比（约 80% / 95% 阈值）；无出库数据时保持未分类。Min–Max 排除过期库存，低于下限时建议补到目标量。仅建议，不自动采购或入库。
- 配送完成时只记账一次。任务、当前位置、批次库存和流水通过既有 MySQL 状态事务保存，操作日志写入现有日志表。
- 三种数据模式分别保存物流状态。切换模式暂停原任务。真实模式或已启用真实 AGV / 仓储接入时，拒绝模拟下发，仅提供预览。

## 边界

- 24 × 16 米布局为演示坐标，不是现场测绘。没有接通实车定位、交通管制、导航地图或设备控制。不能直接用于真实 AGV 导航。
- 页面入库是人工确认的交接，不自动从生产计数生成库存。当前两个演示产品为青柠气泡水和苏打水。
- 仓储按六个逻辑库位管理，一格对应一个批次；模型托盘不是实际库存，货物标记表示批次占用，不按箱数绘制所有纸箱。
- C-HD 未加入：尚无可核实的算法定义与实现依据，不将其他算法改名展示。
- Blender 中蓝线路径是静态预览；网页中的路线、货物和车辆由后端任务驱动。编辑 Blender 后须同步更新空间定义，不能直接改变实车地图。

## 验证

`node --test logistics.test.mjs`：路线最短性、安全膨胀、无路停车、接货前后重规划、库存守恒、调度排序、2-opt 不劣于最近邻、ABC / Min–Max、满库和无效输入。

`node verify-data-modes.mjs`：隔离 MySQL 库中的权限、真实控制阻止、单车并发、暂停及避障等待后的重启、库存恢复、障碍与候选任务持久化、模式隔离和日志。

`npm run build`：前端构建。
