# MG400 单次取放脚本

文件：`mg400_pick_place.lua`。这是 Lua 脚本模板，不是已标定的实机工程。

1. 在 Dobot Studio Pro 创建 Lua 脚本工程，例如 `bottle_pick_place`，将脚本粘贴到主脚本中。
2. 保持 `PREVIEW_ONLY=true`。先用 Studio 编译、运行预览，预期仅打印步骤，不发送运动或 DO 指令。当前尚未在现场 Studio 编译验证。
3. 确认末端工具、用户坐标系、负载设置；通过现场低速示教保存 P1～P6（对应含义见脚本注释）。点位名称必须与脚本一致。核对每一段直线路径和整条机械臂的扫掠空间。
4. 确认气路类型及 DO 接线。当前只提供单 DO 真空阀的模板，未知的编号与电平保持空值。气泵不能直接由普通数字输出驱动；需按设备电气设计连接。若是双阀等其他结构，要先修改吸具控制函数。
5. 首次实际验证先做无工件低速路径检查。待真空吸取可靠、瓶子有支撑、人员远离运动范围后，再测试带工件取放。脚本目前没有吸住反馈，延时不能证明抓取成功。
6. 实际运行之前，人工将空载机械臂置于 P1，再按现场核实结果设置确认项。不要只改 `PREVIEW_ONLY` 便运行。软件确认项不是硬件安全保护。
7. 现场验证后保存工程，再切换到所需远控模式，在平台填写控制器实际保存的工程名。平台运行工程是后续操作，本次未上传、未执行。

脚本只运行一遍，不自动回零、不清报警、不自动重试或恢复。异常停止后不得在悬空持物状态直接从头重跑。

语法参考：Dobot Lua Syntax Guide（https://www.dobot.com.mx/assets/download/m1/user%20guide/Dobot%20Lua%20Syntax%20Guide.pdf）中的 MovL、Sync、DO、Wait、SpeedL、AccL、CP；MG400 Lua 用法另参考 https://github.com/n-speed/MG400-Dobot-Demo 。上述语法资料不等于当前控制器版本兼容验证，以现场 Studio 的 API 提示和编译结果为准。

## 集中配置轨迹与运行参数

- `config/mg400-trajectories.json`：小幅测试起点、相对轨迹、默认轨迹名称，以及取放模板引用的示教点名称。XYZ 单位 mm，R 单位度；取放点的实际坐标仍在 Studio 中示教保存。
- `config/mg400-motion.json`：速度比例、停留时间、吸取/释放等待及单 DO 阀接口参数。速度是百分比，不是 mm/s；默认保留此前测试值。

小幅测试脚本每次启动时读取两份文件，不在运行中热切换路径。原有起点核对、逆解检查、12 mm 范围监控及单次运行行为保留。

完全离线校验（不连接机械臂）：

```powershell
node handoff-examples/mg400-motion-config.mjs --check
```

根据配置生成取放 Lua 预览脚本：

```powershell
node handoff-examples/mg400-motion-config.mjs --export-lua
```

输出 `handoff-examples/mg400_pick_place.configured.lua`，原模板不覆盖。生成结果始终保持预览模式，现场及 IO 确认项重置为 false。将其导入 Studio 工程，核对示教点、编译及现场验证后保存到控制器。平台 RunScript 运行的是控制器工程，不会直接读取电脑上的 JSON 轨迹；改 JSON 后必须重新生成并更新工程。

实时调速仍通过平台“设置速度”并人工确认后下发 SpeedFactor。修改配置文件不会自动改变当前速度；Lua 模板的 SpeedL 与全局 SpeedFactor 是不同设置。MG400 页面与文件现已统一，IP、工程名和默认速度均来自专用配置文件。实时调速只影响本次运行，不自动改写默认值。

吸具默认 unconfigured。接线核实后可以配置 digital-output、output、onLevel/offLevel（0/1）及等待时间，生成单 DO 阀模板。普通开关阀没有力度数值控制能力；pressureKPa 保持 null，填写数值会明确报错。只有核实可调压硬件与通信协议并实现适配后，才能实时调节压力。吸取等待时间不代表吸取力度，也不证明已经吸住。
