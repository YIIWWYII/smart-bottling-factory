# MG400 接入与现场验证

本次将参考项目的 Python socket 通信移植为 Node.js `node:net`，没有启动或依赖其 Python 桌面程序。依据四轴 MG400 TCP 文档（2024-04-19）；六轴 V4.6.0 不作为 MG400 指令依据。

## 已接入

- 工程管理 → 设备配置：MG400 地址、29999 控制端口、30004 反馈端口、控制器内准确工程名。配置随现有业务数据存入 MySQL；服务重启不自动连接或启动设备。
- 工位终端 → 瓶体预处理：MG400 实机面板。上电、使能、下使能、运行工程、暂停、继续、停止、清错、全局速度比例。
- 每项写操作先预览具体目标和指令，再人工确认；确认绑定当前用户和连接，30 秒过期、仅使用一次。模拟模式不可下发实机控制。
- `RunScript(blockly_test01)` 不加引号，不猜测其他工程名，不自动清错、不自动停止已有工程。需要控制器先已使能且空闲。
- 按 1440 字节小端布局解析反馈，校验长度与 TestValue；TCP 分包/合包累计处理。64 位整数以十进制字符串保留，避免 JavaScript 数值精度损失。
- 四个实际关节角、末端 X/Y/Z/R、状态、报警和全部解析字段可查看。报警时补查 GetErrorID。操作与状态变化进入预处理工位日志。
- 实机面板与产线预处理上料位置支持同一简化 MG400 反馈模型。真实/混合模式且已配置地址时，上料模型使用反馈结构，不播放原预制取放动作。未连接时显示未知、保留最后姿态；不伪造取瓶成功或产量。
- 模型结构及轴方向参考同事 Qt Quick 3D 程序，用 Three.js 实现；现场仍需校核零位、旋转方向和安装变换。未将其宣称为已校准模型。

## 现场步骤

1. 在 Dobot Studio 核对机型、控制器版本和安全状态，先验证工程轨迹，再将工程保存到控制器。
2. 切换 TCP/IP 二次开发模式。平台后端电脑与机械臂处于可互通局域网。
3. 平台填写真实 IP、端口和准确工程名；积木工程常带 `blockly_`，以控制器实际名称为准。
4. 保存后点击连接，确认持续收到反馈。先对照 J1–J4 和末端位置，不发运动指令。
5. 切换真实或混合数据模式。现场允许操作后，按状态分别上电、使能、设定速度；每次核对确认弹窗。
6. 运行已验证工程，分别核对“受理 → 运行反馈 → 空闲”。空闲仅表示运行结束，不证明抓取或装箱成功。
7. 验证暂停、继续、停止和断网反馈。断开通信不是停止设备；实际急停使用硬件安全回路。

## 尚需现场资料或验证

- 吸具接口、DO 引脚、吸住检测输入、可调吸力的硬件及寄存器未确认，本次不提供虚假的吸力滑块。
- 平台界面尚未接入 30003 的直接关节运动/回零控制；独立的 `mg400-small-paths.mjs` 已用于现场小幅 MovL 测试，见《MG400小幅轨迹实测.md》。
- MG400 独立操作不等于整线实机启停；其他工位继续保持原接入边界。
- 真实控制沿用平台现有演示角色机制；部署到现场网络前需使用实际身份认证和现场访问控制。
- 已验证本地 TCP 模拟控制器，并于 2026-10-19 验证实机反馈、使能及小幅空载运动；吸取放置和完整产线尚未完成实机验收。

## 模型结构与关节范围（2026-10-19 核对）

当前资产 MG400-TEACH-01 的 `robot-platform.glb` 没有 skins，也没有使用 skin 的节点；Blender 对照场景中没有 Armature 对象或 Armature 修改器。当前已经采用独立刚性部件、Empty 关节轴心与父子层级，不需要删除骨骼。保留 A_j1、A_j2、A_j3、A_j4 及平行连杆从动节点；删除这些节点会破坏机构关系。

以下是 Dobot 官网 MG400 产品规格，**不是从本台控制器读回的软件限位**：

| 实机轴 | 标称角度范围 | 标称最大关节速度 |
| --- | --- | --- |
| J1 | -160°～160° | 300°/s |
| J2 | -25°～85° | 300°/s |
| J3 | -25°～105° | 300°/s |
| J4 | -360°～360° | 300°/s |

来源：https://www.dobot-robots.com/products/desktop-four-axis/mg400.html （Range of Motion / Maximum Joint Speed）。额定负载 500 g，最大负载 750 g，工作半径 440 mm；工具、吸具和工件均需纳入实际负载评估。最大速度是规格上限，不是当前演示速度，也不是推荐运行速度。

官方 MG400_ROS 仓库 URDF 的 limit 值与产品规格存在差异，例如 J1/J4 约 ±180°，J2 约 -8°～80°，J3 约 0°～80°；因此本项目不把 URDF 的这些数值当成实机安全限位。

公开的四轴 TCP 文档及当前 1440 字节反馈布局未发现用于读回关节上下限的字段/指令。本机软件限位、安装姿态、工具偏移和机构耦合限制仍需在 Studio 的实际设置及对应版本说明中核对，目前标为“未读取”。不能靠驱动机械臂到极限来探测范围。各轴单独在标称范围内，也不保证组合姿态可达或整段路径无碰撞。

映射时应使用实际 q_actual 驱动刚性部件。超出预期范围时应提示核查原始反馈/坐标定义，不能静默裁剪角度来掩盖问题；模拟滑块的限值也不能替代控制器的实际安全设置。此次没有修改控制器限位或发送运动指令，也尚未把 Blender 原模型切换为实机反馈驱动。

## 设备配置与验证

设备配置页左侧读取当前设备资产，右侧按设备编号独立保存连接资料。MG400 选择“TCP · Dobot MG400”，IP 是该连接的目标地址，不是另一种通信方式。其他设备可选择 HTTP、Modbus TCP、通用 TCP、MQTT 或 OPC UA；Modbus 需要已有点位表，通用 TCP、MQTT、OPC UA 目前仅登记资料，尚未接入采集驱动。选择其他协议编辑资料不会自动断开已有 Dobot 连接。

`node --test mg400.test.mjs loading-zone.test.mjs robot-motion.test.mjs`

涵盖：小端数据、64 位精度、错误帧、分包合包、确认过期与用户绑定、不加引号工程指令、受理不等于完成、控制器拒绝、反馈过期、已有模拟上料动作回归。

## 专用模型映射配置

文件：`public/config/mg400-model-mapping.json`。实机面板和产线上料位置的简化反馈模型共用此文件，不在页面提供编辑表单。浏览器运行时读取，修改后刷新网页生效；生产部署修改 `dist/config/mg400-model-mapping.json`，无需重新编译 JS。后续重新构建会用 public 中的文件覆盖 dist，因此应同步保留源文件的修改。

- `feedbackField`：反馈里的数组字段，当前为 `q_actual`，依次取 J1、J2、J3、J4，单位为度。
- `staleAfterMs`：反馈超过多少毫秒未更新则保留最后姿态。
- `bindings[].target`：当前模型节点 `j1`、`j2`、`j3`、`wrist`、`j4`，每个节点必须且只能出现一次。
- `axis`：该节点的局部旋转轴 `x`、`y` 或 `z`。
- `weights`：J1～J4 的四个系数；`[0,-1,0,0]` 表示取 J2 的反向角度，`[0,1,1,0]` 表示 J2＋J3。
- `offsetDeg`：模型零点偏移，单位为度。

计算规则：模型角度 = J1×系数1＋J2×系数2＋J3×系数3＋J4×系数4＋零点偏移，最后转为弧度。它是相对于该节点父级的旋转角，不是世界坐标角。默认配置保持原来的显示关系。

配置缺失或格式错误时停止更新模型，并在模型状态中显示原因，不悄悄使用另一份默认映射。离线、过期、缺失或非有限角度不更新任何关节。不按标称范围裁剪实机反馈，不从此文件修改控制器限位或发出运动指令。

当前此配置已用于简化反馈模型。Blender 原始模型的 Empty 节点名称及局部坐标系不同，尚未接入实时反馈；不能直接把 target 改为 A_j1 就视为完成 Blender 绑定。

## 四类配置文件

文件均位于项目 config 目录。平台在断开通信时读取并保存文件，下次连接加载最新文件；独立脚本每次启动读取。不自动连接或执行设备。

| 类别 | 文件 | 职责 |
| --- | --- | --- |
| 1 通信 | mg400-communication.json | IP、TCP、协议选择、控制/反馈/运动端口、连接和命令超时 |
| 2 协议与字段 | mg400-protocol.json | 1440 字节反馈帧、小端字段布局、校验标识，以及平台控制命令模板、参数类型和范围 |
| 3 接收 | mg400-acquisition.json | 主动推送接收模式、反馈有效时间 |
| 4 下发：轨迹 | mg400-trajectories.json | 默认控制器工程名、小幅测试路径、取放示教点名称 |
| 4 下发：其他参数 | mg400-motion.json | 默认平台速度、脚本速度/加速度、停留、吸具接口及等待参数 |

原 mg400-feedback.json 已合并到 mg400-protocol.json 的 feedback.fields，不再保留两份定义。字段仍为 [名称, 字节偏移, 类型]，B/H/Q/d 表示 1/2/8 字节无符号整数和 8 字节浮点数，数字前缀为数组长度。解析器负责持续组帧；字段必须遵循实际协议，不是任意调整。

接收与下发共用通信配置。协议文件中的 commands 定义平台按钮对应的控制命令，参数经过类型检查后替换，不执行配置中的 JavaScript。命令应答解析和运行状态、人工确认检查继续由 MG400 驱动负责。当前只实现 MG400 四轴 TCP 协议，改协议名称不会自动适配其他设备。

MG400 以这五份文件为唯一配置来源。首次启用时将原数据库中的 IP、端口、工程名和速度迁入文件，communication.platformManaged 标记迁移完成，此后不再从数据库覆盖文件。其他设备继续使用原有配置。独立小幅测试脚本直接读取相同文件。修改参数文件不会实时自动调速。

模型显示映射仍独立位于 public/config/mg400-model-mapping.json。吸取力度尚无可调压硬件适配，pressureKPa 保持 null。轨迹引用控制器工程时，实际轨迹需要在 Studio 中保存到控制器；本地取放配置通过导出 Lua 预览脚本使用，详见轨迹脚本使用说明。

## 在平台编辑机械臂配置

入口：MG400 面板 → 配置文件。五个分类分别对应磁盘中的五份 JSON，可切换、编辑、校验保存、重新读取或撤销草稿。页面显示实际文件路径。管理员和工程师可配置；只有断开通信后才允许保存，避免运行中换解析规则。断开通信不等于停止机械臂。

保存只更新当前文件；文件已被本机编辑器或其他页面修改时，旧草稿拒绝覆盖，先撤销或另存草稿再重新读取。通信、工程名称、速度设置均以文件为准。连接按钮独立于保存；执行动作仍经过原人工确认流程。速度下发是本次运行操作，不自动改写文件中的默认速度。

协议页面可检查完整字段；安全状态字段、官方指令格式禁止任意替换，速度允许范围可以收窄。界面不会把协议名称修改视为已实现新协议。
