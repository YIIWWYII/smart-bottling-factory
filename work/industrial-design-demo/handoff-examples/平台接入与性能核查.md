# 平台接入与性能核查

核查日期：2026-10-19。以下区分已验证功能、演示功能与未接入能力。

## Coze 智能体与 Skill

平台接入 Coze 原生自主规划智能体，已发布工具中包含 `list_skills`、`use_skill`。模型自行选择技能，加载 `skills/<英文标识>/SKILL.md` 与 `agents/platform.yaml` 后继续调用允许的工具。不是按关键词替模型选择工作流。

实际请求“帮我分析当前告警”完成 `use_skill → query_logs → 回答`；无需斜杠命令。普通问题“彩虹如何形成”直接回答，没有调用工业工具。工具兼容代理保留模型选择的工具名和参数，只去掉工具调用附带的解释文字，避免 Coze 将其当成普通回答；当前代理会等待上游完整回答再发送流式结果，并非逐 token 实时输出。

写入工具仅生成待确认单，不能直接操作设备；服务端按用户、请求范围和技能工具权限检查。相关自动测试覆盖无授权请求、独立预览不能写入、提案去重及技能越权。此次端到端检查没有执行设备控制。

当前本地 Qwen3.5-4B 使用 CPU 推理。此前进程退出日志为 `CUDA error: unknown error`，不能据此认定显存耗尽。`start-chat-model.ps1` 默认 GPU 层数为 0，可显式传入 `-GpuLayers`；该参数与网页渲染模式独立。

## 视觉与助手交接

AI 视觉有顶部、侧面 0°、120°、240°四机位，可同步或分别设置服务地址、模型名、连接方式。保存后测试连接；HTTP 检测服务必须符合 Bottleworks 契约。多个机位地址、模型名相同时合并请求，不同时分别请求再汇总。

摄像头预览使用真实视频/MJPEG 网关；3D、2D预览使用平台数据。读取实际帧需要相机网关允许跨域读取。没有相机显示“暂无实际画面”。每3秒连续识别不会叠加未完成请求。

模型文件先上传，再交给检测服务加载；网页不能直接运行任意格式权重。智能体 JSON 可以提取名称和 ID，但仍需要在 Coze 导入、发布。服务“已启用”不代表连接或推理已经验证成功。

实际验证：现有固定演示服务四路齐全返回通过，缺侧面240°转复检。结果保留 `demo:true`。不同服务路由、缺图和错误请求编号另有自动测试。尚未接入真实摄像头、训练好的视觉模型，因此不能声称真实识别准确率或现场效果已通过。

配置页在1366px桌面宽度和390px手机宽度下未发现横向溢出。本次未重复运行完整3D压力测试。

## 程序、数据与模块边界

已分离的内容：MySQL业务数据与接入配置；文件形式的Skill、知识库；独立模型与图片资源。服务端按职责已有视觉路由、技能配置、Coze工具桥接等模块。

尚未全面分离：`src/data.js`仍含代码内的工艺预设。设备能力和告警规则已提取至`config/device-capabilities.json`及`config/alarm-rules.json`，但属于随构建发布的静态配置，不是在线热更新。`operations-server.mjs`职责较多；`TwinState.jsx`通过共享Context广播状态，实时更新仍可能使多个页面组件重渲染。现已保留未变化的快照分支，避免资产和控制配置仅因轮询生成新对象就触发重复处理。渲染组件也包含部分业务动作逻辑。因此目前只能称部分模块化，不能称全面高内聚、低耦合。

这次没有把所有业务代码重新拆分，以免改变已有产线行为。后续若继续整理，应先拆出设备状态与配置数据订阅，再逐个迁移工艺规则，并验证模拟、真实和混合模式的一致性。

## 性能与限制

此前确认过普通Chrome使用Microsoft软件渲染器，3D负载落在CPU；启用GPU后单工位抽样曾达到约51FPS，此数值不代表整个系统。之后发生CUDA异常，不能保证开启GPU后稳定。

当前提供软件、混合节能、硬件加速三档，默认软件渲染。桌面启动器按设置打开独立浏览器窗口；软件模式使用SwiftShader，保留3D但速度可能降低。普通网页不能自行切换浏览器的绘制后端。混合节能使用GPU绘制并限制像素倍率和主要视图帧率，不是将同一绘制任务任意分给CPU、GPU。

已限制渲染像素倍率、主要实时视图帧率，减少四路相机的大对象序列化；隐藏页面暂停定时拉取状态，返回页面时立即刷新。后台进程与大模型仍会占用各自资源。构建仍有较大代码分块提示，未宣称全部性能问题已经解决。
