# 瓶安视觉实训操作教程

本教程对应稿件 2.1～2.8、3.1～3.3 和 4.5。使用当前电脑的 YOLO12、OpenCV、PatchCore 和 Docker 环境。每节按“准备材料 → 实际操作 → 检查结果”完成。

## 开始前：打开软件与工作目录

1. 在 Windows 开始菜单搜索 Docker Desktop，点击打开。等窗口显示 Docker 引擎正在运行。
2. 按键盘 Win + E 打开文件资源管理器。点击上方地址栏，粘贴 `E:\2026挑战杯\工业沙盘2026\数字展板前后端\work\industrial-design-demo\vision`，按 Enter。
3. 在文件夹空白处右键，选择“在终端中打开”。如果没有这一项，在开始菜单搜索 PowerShell 并打开，然后执行下面第一行。
4. 逐行粘贴下面的命令，每行按一次 Enter。命令前面的 `PS ...>` 是终端提示符，不需要输入。

```powershell
Set-Location 'E:\2026挑战杯\工业沙盘2026\数字展板前后端\work\industrial-design-demo\vision'
docker compose up -d
docker compose ps
```

看到 vision 服务为 Up 或 running 后，在 Chrome 地址栏输入 `http://127.0.0.1:8095/`。页面标题应为“瓶安 · 视觉实训”。如果终端提示无法连接 Docker，先返回 Docker Desktop 等待引擎启动，再执行一次 `docker compose up -d`。

这台电脑已安装依赖和模型，无需从头安装。Docker 是运行视觉程序的独立环境；PowerShell 用于输入命令；Chrome 用于采集图片和查看检测结果。模型、样本、输出放在 `F:\BottleAI\vision`。

## 2.1 技术简述与机位布置

**本节完成后：** 能区分四个机位，为同一瓶子采集图像，并保存样本。

![四机位布置示意图，非实物照片](media/camera-layout.svg)

顶部机位检查瓶盖，三个侧面机位分别对应 0°、120°、240°。`top`、`side-0`、`side-120`、`side-240` 是程序使用的四个机位名称。

1. 在测试页点击“开启电脑摄像头”。浏览器询问权限时选择“允许”。看到实时画面后，把瓶子放到镜头前。
2. 页面机位下拉框选择“侧面 0°”。瓶子编号填 `BOTTLE-001`，批次编号填 `DEMO-001`。
3. 调整距离，使瓶子清晰、完整地出现在画面中。点击“将当前图加入所选机位”，下方应出现缩略图和 `1 / 4 个机位`。
4. 转动同一瓶子，依次采集侧面 120°、侧面 240°；拍摄顶部时调整摄像头或瓶子的相对位置。每次先改机位，再点击采集按钮。
5. 同一瓶的四张图使用相同瓶号和批次。换瓶子时修改瓶号，页面会清空上一瓶的采集图。
6. 要保存训练图片，在“保存样本”左侧选择“确认正常”“存在缺陷”或“待确认”，再点击“保存样本”。状态栏会显示文件保存位置；保存后的文件位于 `F:\BottleAI\vision\captures` 下。
7. 结束采集后点击“关闭摄像头”。

一台电脑摄像头可用于逐角度练习，不能验证四台相机同时采集。正式演示需要同一瓶子的四视角图片；当前未准备完整的独立四视角测试集。

## 2.2 图像预处理与检测区域

**本节完成后：** 看懂原图、裁剪图、对齐图和排除区域，知道配置保存在哪里。

OpenCV 在检测前处理图像。“裁剪”是保留瓶子所在部分；“对齐”是根据参考图修正小幅位置、角度偏差；“排除区域”是本次不参与检测的范围。

1. 保持 PowerShell 位于 vision 文件夹，执行下面命令。它只生成教学预览，不修改在线配置。

```powershell
docker compose exec -T vision python tutorial_preprocess.py
```

2. 按 Win + E，在地址栏粘贴 `F:\BottleAI\vision\tutorial\media`。分别双击 `opencv-original.jpg` 和 `opencv-crop.jpg`，比较原图与裁剪结果。

![原始图片：包含多个瓶子](media/opencv-original.jpg)

![裁剪后：仅保留中间瓶子的示例区域](media/opencv-crop.jpg)

3. 打开 `opencv-offset.jpg` 和 `opencv-aligned.jpg`。前者是在裁剪图上人为平移 7 像素、4 像素生成的教学输入，后者是实际调用 OpenCV 对齐后的结果。这个例子用于理解对齐，不代表已经验证现场相机。

![人为偏移的教学输入](media/opencv-offset.jpg)

![OpenCV 对齐结果](media/opencv-aligned.jpg)

4. 打开 `opencv-excluded.jpg`。灰色矩形不参与本例的有效区域检测。这是坐标示例，尚未认定为实际生产码的位置。

![排除区域示例：灰色矩形](media/opencv-excluded.jpg)

5. 在资源管理器找到 `F:\BottleAI\vision\config.json`，右键选择“打开方式 → 记事本”。先阅读 `cameras` 下的 `side-0`，找到 `preprocess`。

| 字段 | 含义 | 填写方式 |
|---|---|---|
| roi | 从原图裁剪的范围 | `[左, 上, 右, 下]`，每项为 0～1；`[0,0,1,1]` 保留整图 |
| size | 处理后的图片边长 | 当前为 320 像素 |
| reference | 对齐参考图 | 相对 `F:\BottleAI\vision` 的路径；当前在线配置未启用参考图 |
| exclude | 不参与检测的矩形范围 | 使用处理后图片的 0～1 坐标；`[]` 表示不排除 |

6. 需要修改在线配置时，先在资源管理器复制 `config.json`，粘贴一份备份，再编辑原文件。保留英文引号、逗号和方括号，按 Ctrl + S 保存。
7. 修改裁剪、对齐或排除区域后，需要同步处理训练图片与标注，并重建对应 PatchCore 库。现有训练脚本会拒绝直接沿用旧标注训练新的裁剪区域，因此不要把上方教学坐标直接写进在线配置。

## 2.3 准备数据集并用 LabelImg 标注

**本节完成后：** 能找到样本，打开标注软件，为污渍画框、填写类别，并检查保存的标签。

### A. 找到数据集

1. 打开资源管理器，地址栏粘贴 `F:\BottleAI\vision\datasets\local-blot-normal`。
2. 打开 `images\train` 查看训练图片，再回到上一级打开 `labels\train`。图片与标签文件名相同，扩展名分别为 `.jpg` 和 `.txt`。
3. `images\val` 与 `labels\val` 是验证图片及标签；`data.yaml` 告诉训练程序去哪里读取这些文件。

```text
local-blot-normal
  images
    train     训练图片
    val       验证图片
  labels
    train     训练图片对应的标签
    val       验证图片对应的标签
  data.yaml   数据位置和类别名称
```

当前副本有 104 张训练图片、42 张验证图片，已去除完全重复的图像。原始样本保留在微信文件目录，教程练习不修改原图。

![数据集与标签清单：根据本机实际目录生成](media/dataset.png)

### B. 采集或下载补充数据

实际产品优先按 2.1 节采集。正常图片应包含允许范围内的反光、印刷和位置变化；缺陷图片应有清晰可见的缺陷。正常图保存为空标签，不画缺陷框。

公开数据已准备在 `F:\BottleAI\vision\datasets\public\mvtec-bottle`。打开 `train\good` 查看正常图片，打开 `test` 查看不同测试类别。需要补全下载时，在 vision 目录的 PowerShell 执行：

```powershell
python download_public.py
```

此脚本下载 MVTec AD bottle，已有文件会跳过。完成后应有 209 张正常训练图、83 张测试图和 63 张缺陷掩膜。来源是 Voxel51 的 MVTec AD 镜像，许可为 CC BY-NC-SA 4.0；该数据是玻璃瓶口图，适合单独练习 PatchCore，不直接混入饮料瓶身正常库。

### C. 打开 LabelImg

1. 在资源管理器打开 `F:\BottleAI\vision\tutorial\practice`。
2. 双击 `启动标注.cmd`。它使用本机已安装的 LabelImg，并预设练习图片和标签目录。
3. 如果没有自动显示图片，点击左侧 `Open Dir`（打开图片文件夹），选择该目录下的 `images` 文件夹。
4. 点击 `Change Save Dir`（选择标签保存位置），选择该目录下的 `labels` 文件夹。
5. 检查左侧格式按钮显示 `YOLO`。如果显示 `PascalVOC`，点击该按钮切换到 `YOLO`。

![LabelImg：图片、工具栏与 YOLO 格式按钮](media/labelimg-open.png)

### D. 框选污渍并保存

1. 观察中间茶饮瓶上的黑色污渍。点击左侧 `Create RectBox`，或按键盘 W，进入画框模式。
2. 在污渍左上角按住鼠标左键，拖到右下角后松开。框应包住可见污渍，尽量少包含正常图案。
3. 弹出类别窗口后输入 `blot`，点击 `OK`。右侧 `Box Labels` 列表应出现 `blot`。
4. 相互分离的污渍分别画框。练习图的已有参考标注包含三个区域；可用下方完成图对照。
5. 按 Ctrl + S，或点击左侧 `Save`。打开 `practice\labels`，应看到 `blot-example.txt` 和 `classes.txt`。

![输入污渍类别 blot](media/labelimg-class.png)

![三个污渍框与保存后的标签列表](media/labelimg-saved.png)

VIDEO: media/03-labelimg.mp4

录屏使用 LabelImg 实际界面，通过自动输入复演画框、填写类别、保存标签。只操作练习副本；截图中的框参照已有人工标注，不作为新的独立测试答案。

6. 用记事本打开 `blot-example.txt`。每行五个数，分别为类别编号、框中心横坐标、框中心纵坐标、框宽、框高。后四项都是相对于图片大小的 0～1 数值。当前 `classes.txt` 只有 `blot`，所以类别编号为 0。

稿子还展示 `scratch`（划痕）和 `damaged`（破损）。画框操作相同，但当前训练脚本只支持 `blot`。现阶段可练习污渍标注；三类完整训练还需补齐对应样本，并修改数据配置及训练脚本，不能仅在 LabelImg 中增加名称后继续使用当前单类训练命令。

### E. 划分数据与检查

训练集用于学习，验证集用于选择参数和权重，独立测试集留给测试岗位检查最终结果。同一瓶子或连续拍摄的近似图片应放在同一个集合中。先按瓶号分组，再分配到集合，随后检查每张图是否有同名标签。

现有数据保留原始训练/验证划分，尚未核实瓶号分组，也没有独立现场测试集。这些条件需要在正式验收前补齐。27 张无标签图片已确认为正常图，已纳入副本，无需再标缺陷框。

## 2.5 PatchCore 正常特征库构建

**本节完成后：** 理解正常库的作用，会运行建库程序并找到生成文件。

1. 在资源管理器打开 `F:\BottleAI\vision\datasets\water-front\train`。这里是当前矿泉水侧面实验用的正常图。
2. 对照产品和机位。建库图片、阈值验证图片、独立测试图片分开保存，同一连续序列不拆散。当前只有 3 张去重后建库图片及另 1 张阈值试验图，适合流程练习，数量不足以验收。
3. 在 vision 目录的 PowerShell 执行：

```powershell
docker compose exec -T vision python train_patchcore.py --normal /data/datasets/water-front/train --camera side-0 --output /data/tutorial/practice/water-front-patchcore.pt --ratio .02 --experimental-small-set
```

这会生成练习特征库，保留在线特征库。`normal` 是正常图目录，`camera` 是机位，`output` 是生成文件；`/data` 对应电脑上的 `F:\BottleAI\vision`。末尾参数允许少量样本练习，不能说明样本量足够。

4. 等待命令结束，打开 `F:\BottleAI\vision\tutorial\practice`，确认生成了 `water-front-patchcore.pt`。
5. 查看下方本次建库输出，最后一行应显示保存路径。`threshold not calibrated` 表示尚未为这份新库校准阈值。

![PatchCore 建库日志与实际生成文件](media/patchcore-output.png)

6. 了解已有在线实验的阈值记录：打开 `F:\BottleAI\vision\verification\local-patchcore-calibration.json` 查看记录，再查看 `config.json` 的 `side-0`，核对 `patchcore` 路径与 `anomalyThreshold`。

本实验用一张正常图的分数加 5% 作为临时阈值。正式阈值需用更多正常与缺陷验证图确定；目前保留实验模式，两条分支均未发现问题时仍返回复检。其余三个机位尚无对应正常库。

## 3.3 整瓶判定与耗时检查

1. 在每次整瓶检测结果中记录瓶号、各机位状态、最终状态及 `durationMs`。
2. 有明确不合格缺陷时应为不合格；无明确缺陷但有外观异常、缺图或失败时复检；全部有效检查通过后才允许通过。
3. 核对业务规则之外，还需确认最前面的四机位采集检查是否通过。当前严格接口缺图时直接复检，不运行模型。
4. 用现场计时从开始采集到收到整瓶结果，记录总耗时，再与事先约定的产线节拍比较。页面中的服务处理时间不能代替总耗时。
5. 未约定节拍或未完成实物采集时，表中填写实际情况，不填写节拍验收通过。

## 4.5 视觉服务接入平台

**本节完成后：** 能填写视觉服务信息，测试连接，并核对返回结果的编号和状态。

1. 保持 Docker 视觉服务运行。打开平台 `http://127.0.0.1:5174/?course=connections#admin`。
2. 进入系统配置中的 AI 视觉，选择需要配置的机位。四机位共用本机服务时，可使用同步配置。
3. 选择“YOLO12 + PatchCore（本机实验服务）”预设；服务地址填写 `http://127.0.0.1:8095`，模型名填写 `yolo12-patchcore-experimental`，连接方式选择 Bottleworks HTTP。本机未设置令牌，令牌输入框留空。
4. 点击保存，再测试连接。失败时先在 Chrome 打开 `http://127.0.0.1:8095/health`，确认视觉服务本身可以访问。
5. 上传四机位图片，检查返回的瓶号、批次、机位和最终状态。缺图或失败不能记成通过。
6. 在平台检测记录中核对原图、结果图、时间和版本，并将截图放入对应测试用例。

## 附录：文件位置与遇到问题时的检查方法

- **找不到标注结果**：检查 LabelImg 的 `Change Save Dir` 是否指向 `practice\labels`，以及格式是否为 YOLO；XML 文件说明保存成了 PascalVOC。
- **摄像头没有画面**：使用 Chrome 或 Edge，检查地址栏摄像头权限，关闭其他占用摄像头的软件。
- **训练报 ROI 错误**：现有标签基于整幅图；恢复与训练数据对应的配置，或先完成新区域的标注转换。
- **没有热力图**：确认选择 side-0；其他机位当前没有正常库。整瓶缺图时不运行推理，也不会生成热力图。
- **出现复检**：查看 reason。缺图、缺模型、异常分数超阈值和实验模式都可能返回复检。
- **移动教程**：复制整个 `F:\BottleAI\vision\tutorial` 文件夹。网页和媒体可以离线查看；训练、标注启动器和服务连接仍依赖本机安装路径。
