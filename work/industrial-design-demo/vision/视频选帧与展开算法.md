# 四机位视频选帧与瓶身展开

在 VS Code 中打开 `视觉算法.code-workspace`。算法源文件是 `video_workflow.py`，参数放在 `video_workflow.json`，测试是 `test_video_workflow.py`。

## 本轮实现范围

离线读取四路视频 → 各路检测并跟踪前景目标 → 顶部轨迹依次编号 → 各路经过时间段中点选帧 → 按已标定的时差关联 → 三侧面圆柱投影展开与重叠融合 → 参考图对齐 → 多边形码区遮罩。

目前检测器是固定空背景差分，并非训练好的瓶体或瓶盖模型。背景必须为空、相机固定、光照稳定；其他移动物体也可能被检出。`detect_foreground` 是后续接入训练好的瓶盖/瓶体检测器的位置。几何跟踪发生歧义时保留复检，不尝试猜测身份。

目前是离线恒定帧率视频实现，不是实时四相机采集。时间采用帧号除以 FPS，加机位时钟偏移；可变帧率视频应先转换为恒定帧率，实时系统应使用相机采集时间戳。配置的时间偏移和输送时差必须实测，不能从视频文件开始时间推断。

## 在 VS Code 终端运行

1. 打开 VS Code，选择“文件 → 从文件打开工作区”，选择上述工作区。
2. 选择“终端 → 新建终端”。打开 Docker Desktop，确认引擎已运行。
3. 本次合成素材已经保存在 `F:\BottleAI\vision\experiments\video-workflow-fixture`。四个文件是 `top.mp4`、`side-0.mp4`、`side-120.mp4`、`side-240.mp4`。
4. 执行下列命令。输出目录必须是新目录，已有结果不会覆盖：

```powershell
docker compose exec -T vision python video_workflow.py --profile /data/experiments/video-workflow-fixture/profile.json --videos /data/experiments/video-workflow-fixture --output /data/experiments/video-workflow-replay-01 --synthetic-fixture
```

5. 打开 `F:\BottleAI\vision\experiments\video-workflow-replay-01`。`report.json` 记录所有轨迹、进入离开时间、选中帧、关联错误及结果。每个 `BOTTLE-...` 文件夹保存四张选中帧、展开图、对齐图、遮蔽后的图和有效区域掩膜。
6. 检查合成例中应有两个瓶号，四个机位都有对应轨迹。最终状态保持 `review`：它没有使用真实四路相机，也没有训练匹配展开图的缺陷模型。

执行测试：

```powershell
docker compose exec -T vision pytest -q -p no:cacheprovider test_video_workflow.py test_pipeline.py
```

## 参数如何调整

| 参数 | 含义 |
|---|---|
| cameras.*.roi | 各画面跟踪区域，归一化左上右下坐标 |
| backgroundFrame | 没有瓶子经过时的空背景帧编号；不是随意选第一帧 |
| timeOffsetSeconds | 把该文件时间转换到同一个时钟，单位秒 |
| travelDelaySeconds | 相对顶部机位的实际到达时差，单位秒 |
| association.toleranceSeconds | 关联允许误差，需要小于能区分相邻瓶子的间隔 |
| maxGapSeconds | 目标暂时消失后允许继续同一轨迹的最长时间 |
| sharpnessMinimum | 清晰度阈值，需要按相机和图像尺寸验证 |
| angleDegrees | 侧面相机绕瓶身的角度，不是瓶子在图中的旋转角 |
| bodyRoi（可选） | 在目标框内裁取直筒瓶身，排除瓶肩和瓶盖；格式同 roi |
| unwrap.excludePolygons | 展开图上的多个码区多边形，坐标取值 0～1 |
| unwrap.reference | 展开参考图相对配置文件的路径，分辨率须与输出一致 |

时间中点处有完整清晰帧时选它；当检测到明显速度变化或中点帧不合适时，选最靠近拍摄区中心的清晰帧。进入、离开时间是前景检测到的边界，存在一个采样帧左右的误差。视频开始时已有目标或结束时目标尚未离开，则该轨迹不用于正常判定。

匹配使用时间窗口的一对一对应。少一个侧面事件不会使后面的瓶号整体前移；同一窗口存在多个候选、同一候选对应多个顶部轨迹时标记歧义。无法从仅有画面和时间绝对证明物理身份，真实产线仍需验证漏检、遮挡、瓶子旋转和停线场景。

## 展开算法的条件

当前采用近似正交投影的圆柱模型，横向坐标满足 `x = cx + r × sin(角度差)`。三个机位各提供可见角度内的表面采样，在重叠区域按角度权重融合；覆盖有空洞或重叠差异过大时转复检。

这不是任意图片全景拼接。要求瓶身近似直圆柱、保持直立、不在不同拍摄时刻自转，三路裁剪覆盖同一轴向范围。镜头畸变和明显透视尚未自动校正，真实部署前需相机标定；瓶肩、方瓶、凹凸瓶和强反光不能直接使用本算法。重叠差异检查只能提示部分不一致，不能证明拼接完全准确。

参考图对齐只允许水平平移，支持圆周接缝；明显竖直偏差返回复检。码区遮罩保留为独立 `valid-region.png`，原图不覆盖。

## 模型衔接状态

现有 YOLO12 和 PatchCore 使用单视角图片训练，不能把它们直接套到展开图并声称检测有效。本模块目前输出模型所需的展开图、遮罩和记录；`inspection.enabled` 保持 false。打开它会明确返回未支持的模型接入状态。

下一步需要采集同瓶四路视频，标定机位与瓶身区域，生成正常及缺陷展开图。在展开图上重新标注和训练 YOLO12，按相同展开和遮罩流程建立 PatchCore 库，再连接两条推理分支。顶部瓶盖模型单独准备，最后汇总到同一瓶号。

本次合成视频只用于验证算法行为，不作为训练样本、物理同瓶关联证明或检测精度成绩。
