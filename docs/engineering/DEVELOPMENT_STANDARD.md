# 开发与验收标准

## 通用完成定义

每个分支同时满足以下条件才可交给融合对话：

1. 只修改被分配工程；公共契约改动有影响和迁移说明。
2. 能从全新工作区构建，不依赖未提交文件、IDE 私有配置或 C 盘绝对路径。
3. 后端不可达、WebSocket 断开、空数组、缺字段和未知状态不导致崩溃。
4. 模拟数据明确显示来源；写操作绝不模拟成功。
5. 按钮可操作或明确禁用并说明原因，不允许只有样式的假按钮。
6. 页面可滚动，平板/小屏不遮挡关键操作，加载、空、错、离线状态齐全。
7. PR 包含测试证据、已知风险和复现步骤，禁止直接推 `main`。

## 数字展板标准

### P0 必须完成

- 启动直接进入全局总览，不要求登录，不出现管理和控制入口。
- 总览上部为完整连续流程；点击工序进入工位详情；下部显示生产、质量、设备、异常、物流仓储和产品追踪指标。
- 工位详情上部为 2D/3D 动画，下部为设备、物料、质量门、报警和上下游影响。
- 2D 和 3D 都必须由 HarmonyOS ArkWeb `Web` 组件加载 HAP `rawfile` 中的本地 Three.js 页面。禁止改成 ArkUI 原生绘图、在线网页或 CDN。2D 是独立平面工艺符号和路径，3D 是立体设备模型；禁止把 3D 改相机冒充 2D。
- 二者由同一实时快照驱动速度、动作、物料位置、状态颜色和暂停恢复。可分别关闭；关闭后停止渲染并释放不需要的资源。
- 点击设备显示编号、作用、状态、来源、参数和读数；点击物料显示追踪号、瓶型、工序、质量事件和时间。
- 支持设备拖拽布局，位置按“工序 + 视图模式”保存；状态着色可开关，文本状态始终显示。

### P1 完善项

- 全局流程缩略动画、报警定位、产品追踪搜索、全屏展示、性能质量档和掉帧监测。

## 小屏终端标准

### P0 必须完成

- 启动进入设备绑定的当前环节首页；未绑定时先选择工位，不经过大屏/后台入口。
- 当前环节首页必须先完整展示该环节的名称、运行状态、2D/3D 实时作业画面、设备、在制品、传感器、质量门、缓冲、报警及上下游影响，然后再展示参数调整和控制区。
- 当前环节展示与数字展板对应工位使用相同接口、字段、状态和实时数据。其 2D/3D 同样必须由 ArkWeb `Web` 内嵌 HAP 本地 Three.js，支持暂停、恢复、独立开关、着色和设备/物料查看。
- 每个工序分别定义可调设备、参数、单位、范围、步长、角色和联锁，禁止一套通用参数覆盖所有设备。
- 控制闭环：显示当前值、编辑、前端校验、二次确认、HTTP 创建命令、等待回执、展示最终结果和审计号。
- 设备离线、报警、质量门失败、权限不足或后端不可达时，危险操作必须禁用。
- 本地演示只允许浏览，不允许伪造真实控制成功。

### P1 完善项

- 扫码绑定工位、值班交接、常用参数方案、离线只读缓存和维护工单入口。

## 后台管理标准

### P0 必须完成

- 登录、注册、会话恢复、退出、角色权限和未授权拦截完整。
- 导航至少包含运营首页、生产任务、异常处置、设备、产品与物料、物流仓储、AI 决策审计、用户权限、系统配置和操作审计。
- 不复制大屏的沉浸动画，也不复制小屏现场调参；管理端负责配置、查询、审批、追溯、报表和审计。
- 所有修改和处置有确认、鉴权、失败反馈和审计记录；演示账号不得发送真实控制。
- 列表具备查询、筛选、分页、详情和空状态，危险操作不可只靠前端隐藏。

### P1 完善项

- 报表导出、阈值版本管理、参数模板审批、审计对比和多厂区/多产线切换。

## 后端标准

### P0 必须完成

- 业务中枢统一维护产品、工位、设备、质量门、异常、命令、物流和仓储状态。
- MQTT 有数据时用实机数据；超时才按设备降级模拟并标记来源/fallback；恢复后平滑切回。
- 关键历史持久化到 MySQL；Redis 只做实时缓存和分布式协调，不是事实数据库。服务重启后追踪、异常、命令、AI 审计和库存不能丢。
- 设备命令执行 RBAC、参数范围、在线状态、质量联锁、幂等、超时和回执校验。HTTP 成功仅代表受理。
- HTTP、WebSocket、MQTT 和 AI/MCP 外部接口分层，业务服务不直接依赖 UI。
- 每个异常策略明确对当前产品、设备、工位缓冲和上下游的影响。

### P1 完善项

- Redis、指标监控、链路追踪、契约测试、数据归档、灾难恢复和多实例部署。

## 构建门槛

- 鸿蒙工程必须使用官方 `devecocli` 在 D 盘英文暂存路径构建，看到 `BUILD SUCCESSFUL` 且生成 HAP。
- 后端运行 `mvn test`；融合时使用 `factory-demo` 启动后完成 HTTP、WebSocket 和三 App 冒烟联调。
- P0 全过才能合入 `main`；P1 可单独排期，但不能用 P1 掩盖 P0 缺陷。
