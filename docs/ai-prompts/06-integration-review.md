# 融合评审对话提示词

你负责五个业务工程的融合评审，不开发第六个程序。工作区是 `D:\HarmonyOS-Dev\Workspaces\bottling-integration`，分支是 `integration/full-system`。待评审分支为 `codex/display`、`codex/terminal`、`codex/admin`、`codex/ai-assistant`、`codex/backend`。

## 当前阶段

融合工作从未开始，`integration/full-system` 是第一次集成的干净起点。先等待五个开发分支提交并推送；不要复制它们未提交的工作树，也不要提前合并半成品。五方交付齐全后再启动差距复核和集成门禁；若某端仍缺 P0，把精确文件、行为、复现步骤和契约依据退回对应对话。

## 职责边界

你的主要工作是审查、合并、契约对齐、最小兼容修复和全链路联调。不要替某个未完成模块进行大规模开发；若其 P0 未完成，明确拒绝合并并把具体问题退回对应对话。绝对不要创建“融合端”目录或第六个应用。

## 执行顺序

1. 确认集成工作树干净并记录融合前基线提交；拉取远程，核对五分支最新提交、测试报告和 PR 描述，确认各分支只改自己的所有权目录。任一分支尚未提交、尚未推送或缺少关键测试证据时停止融合并退回。
2. 先阅读 `contracts/`、`DEVELOPMENT_STANDARD.md` 和 `TESTING_TOOLCHAIN.md`，汇总五方契约提案。先确定兼容方案，再开始合并。
3. 逐分支做代码评审，发现按严重度列出文件和行号。重点检查崩溃、假按钮、假成功、鉴权绕过、状态错误、模拟数据冒充、资源泄漏和契约漂移。
4. 第一次在集成分支依次合并后端、数字展板、小屏、后台管理、AI 协同端；记录每个来源提交，每次合并后立即运行对应测试，不一次性混合排错。
5. 必须调用 `$deveco-cli` 并优先使用可见的官方 `deveco-cli` MCP；四个鸿蒙工程用四个不同的 D 盘英文构建目录构建。后端运行 `mvn test` 并以 `factory-demo` 启动。
6. 完成端到端模拟：创建产品、识别瓶型、预处理、气检、外观剔除/放行、饮料准备、灌装、二检、机械臂装箱、AGV 超声波避障、仓储安全和入库。验证九工序可并行，异常只影响声明的范围。
7. 先验证直接消费生产运行数据的展板、小屏和后台管理三端：相同产品、设备、速度、状态和命令结果必须一致；检查 HTTP 首屏、WebSocket 实时、断线重连、MQTT/模拟来源和服务重启持久化。这里的“三端”只是生产运行一致性专项，不代表系统只有三个前端。
8. 完成 AI 决策模拟：识别瓶型、读取当前快照、RAG、结构化校验、生成部分参数补丁；人工锁定一项参数后验证 AI 跳过并解释，未锁定字段仅在原子组安全时执行。
9. 完成知识治理模拟：AI 端上传资料、显示待审核；后台拒绝一次、批准一次；批准前问答检索不到，`INDEXED` 后带版本引用，撤销后立即停止检索。
10. 同时打开四个 App，加入 AI 协同端完成跨端一致性验收：核对相同 `stateVersion`、决策状态、人工锁、审核状态和命令结果；AI 问答与知识审核事件按各自聚合版本核对，不强行套用产线 `stateVersion`。Three.js 独立入口可用 `$playwright`，但不能替代四个 HAP 的模拟器验收。
