你的主要工作是审查、合并、契约对齐、最小兼容修复和全链路联调。不要替某个未完成模块进行大规模开发；若其 P0 未完成，明确拒绝合并并把具体问题退回对应对话。绝对不要创建“融合端”目录或第五个应用。

## 执行顺序

1. 确认集成工作树干净并记录融合前基线提交；拉取远程，核对四分支最新提交、测试报告和 PR 描述，确认各分支只改自己的所有权目录。任一分支尚未提交、尚未推送或缺少关键测试证据时停止融合并退回。
2. 先阅读 `contracts/`、`DEVELOPMENT_STANDARD.md` 和 `TESTING_TOOLCHAIN.md`，汇总四方契约提案。先确定兼容方案，再开始合并。
3. 逐分支做代码评审，发现按严重度列出文件和行号。重点检查崩溃、假按钮、假成功、鉴权绕过、状态错误、模拟数据冒充、资源泄漏和契约漂移。
4. 第一次在集成分支依次合并后端、数字展板、小屏、后台管理；记录每个来源提交，每次合并后立即运行对应测试，不一次性混合排错。
5. 必须调用 `$deveco-cli` 并优先使用可见的官方 `deveco-cli` MCP；三鸿蒙工程用三个不同的 D 盘英文构建目录构建。后端运行 `mvn test` 并以 `factory-demo` 启动。
6. 完成端到端模拟：创建产品、识别瓶型、预处理、气检、外观剔除/放行、饮料准备、灌装、二检、机械臂装箱、AGV 超声波避障、仓储安全和入库。验证九工序可并行，异常只影响声明的范围。
7. 同时打开三个 App：相同产品、设备、速度、状态和命令结果必须一致；检查 HTTP 首屏、WebSocket 实时、断线重连、MQTT/模拟来源、服务重启持久化。
8. Three.js 独立测试入口可调用 `$playwright` 做 canvas 像素和截图回归；Swagger/辅助 Web 页面可调用 `$browser-harness`。两者都不能替代三个 HAP 在模拟器中的 Test Kit 与视觉验收；仅在 CLI 无法操作 Test Runner/模拟器时调用 `$computer-use:computer-use`。
