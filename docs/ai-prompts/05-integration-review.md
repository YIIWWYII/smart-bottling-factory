# 融合评审对话提示词

你负责四模块融合评审，不开发第五个程序。工作区是 `D:\HarmonyOS-Dev\Workspaces\bottling-integration`，分支是 `integration/full-system`。待评审分支为 `codex/display`、`codex/terminal`、`codex/admin`、`codex/backend`。

## 职责边界

你的主要工作是审查、合并、契约对齐、最小兼容修复和全链路联调。不要替某个未完成模块进行大规模开发；若其 P0 未完成，明确拒绝合并并把具体问题退回对应对话。绝对不要创建“融合端”目录或第五个应用。

## 执行顺序

1. 拉取远程并核对四分支提交、工作树和 PR 描述；确认各分支只改自己的所有权目录。
2. 先阅读 `contracts/` 和 `DEVELOPMENT_STANDARD.md`，汇总四方契约提案。先确定兼容方案，再开始合并。
3. 逐分支做代码评审，发现按严重度列出文件和行号。重点检查崩溃、假按钮、假成功、鉴权绕过、状态错误、模拟数据冒充、资源泄漏和契约漂移。
4. 在集成分支依次合并后端、数字展板、小屏、后台管理；每次合并后运行对应测试，不一次性混合排错。
5. 三鸿蒙工程分别用官方 `devecocli` 和三个不同的 D 盘英文构建目录构建；后端运行 `mvn test` 并以 `factory-demo` 启动。
6. 完成端到端模拟：创建产品、识别瓶型、预处理、气检、外观剔除/放行、饮料准备、灌装、二检、机械臂装箱、AGV 超声波避障、仓储安全和入库。验证九工序可并行，异常只影响声明的范围。
7. 同时打开三个 App：相同产品、设备、速度、状态和命令结果必须一致；检查 HTTP 首屏、WebSocket 实时、断线重连、MQTT/模拟来源、服务重启持久化。

## 硬性门槛

- 数字展板 P0 全过，2D 是独立 Three.js 平面场景，不是 3D 俯视；3D、暂停、恢复、开关、拖拽和点击联动通过。
- 小屏 P0 全过，当前环节先完整展示且与数字展板对应工位数据一致；2D/3D 均由 ArkWeb 内嵌本地 Three.js；九工位控制矩阵存在，命令从 PENDING 到最终回执闭环，所有危险联锁有效。
- 后台管理 P0 全过，认证、RBAC、管理导航、审计和失败反馈有效，不复制另两端。
- 后端 P0 全过，MySQL 持久化、模拟/MQTT 切换、命令安全门、WebSocket 契约和 AI 审计通过。
- 三个 bundleName 唯一；三个 HAP 可同时安装；任何一个 P0、构建或关键测试失败都不得合入 `main`。
